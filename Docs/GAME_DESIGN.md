# Ragna — 개발 기준

Android / iOS, 세로 화면, 오프라인 싱글 플레이, Unity 6 LTS + URP 2D.

전투는 횡스크롤 방식이다. 캐릭터는 왼쪽에서 오른쪽을 향하고 적은 오른쪽에서 접근한다.
자동 타깃은 가로 거리로 선택하며 공격·스킬도 오른쪽으로 전개된다.
사용자 제공 초원·숲·해안·폐성·화산·마성 배경을 5층 단위로 바꾼다.
원본 비율을 유지한 채 길 높이를 맞추고 이미지 내부에서 왼쪽으로 천천히 이동한다.
현재 배경은 한 장의 그림이며 레이어별 패럴랙스는 아니다.
화면 회전이나 수동 이동·점프는 도입하지 않고 기존 물약·보호막 조작을 유지한다.
저장 버전 5는 슬롯 구성과 진행 중인 턴·콤보를 보존한다. 이전 버전의 전투는 준비 상태로 전환하며 레벨·메타 진행과 기존 좌표·직업 변환을 보존한다.
광고·결제·서버 없이 게임 루프를 먼저 완성한다.

## 반드시 지킬 목표

캐릭터 성장은 수치와 동시에 화면에 드러난다. 스킬 1~3 / 4~7 / 8~11 / 12레벨 이상에서
타격 수·크기·색·궤적이 변한다. 전직은 20·60·100레벨에서 장비와 오라를 바꾼다.
스킬 진화는 전직과 별도라서 성장 피드백이 자주 발생한다.

## 플레이 루프

모험가 시작 → 전투 준비에서 공격 배치 → 내 턴에 전체 슬롯 순차 실행 → 적 한 번 공격 → 20레벨에 첫 직업 선택 → 적의 공격 예고 확인 → 물약과 회피 보호막 수동 사용
→ 층 정복 → 세 가지 무작위 강화 중 하나 선택 → 5층마다 보스 → 30층 보스 클리어.
물약 재사용 5초, 보호막 재사용 8초/지속 1.6초. 보호막으로 막으면 다음 내 턴의 첫 공격이 25% 강화된다.
공격 슬롯은 기본 1 + 첫 전직 1 + 전승 횟수. 전승 슬롯은 영구 유지하며 60·100레벨에는 늘지 않는다.
1·2·3·6칸 스킬은 준비 공간을 점유하고 한 턴에 한 번 발동한다. 평타·평타·스킬은 모두 실행한 뒤 적에게 턴을 넘긴다.
전투 중 준비창을 열면 진행 중인 턴을 멈춘다. 수정한 구성은 다음 내 턴부터 적용한다. 자세한 데이터 규칙은 COMBAT_SLOTS.md 참고.
흡혈은 초당 최대 HP의 2%까지 회복 예산이 충전되어 과도한 자동 회복을 제한한다.
HP가 0이 되면 이번 도전은 끝난다. 재도전 시 레벨·강화·층은 초기화된다.
스마트폰을 끈 동안 자동 전투는 진행하지 않는다. 일시정지와 강화 선택 중에도 전투는 멈춘다.

## 전직과 환생

- 시작 직업: 모험가. 20레벨에 검사, 궁수, 법사, 거너, 격투가, 성직자, 도적 중 하나를 선택한다.
- 20레벨 1차 전직 → 60레벨 2차 전직 → 100레벨 3차 승급.
- 승인된 검사 60레벨 분기는 기사/광전사. 다른 분기 직업명과 루트는 사용자와 함께 결정한다.
- 전직은 ScriptableObject 자산으로 정의한다. 부모 ID와 승급 단계를 지정해 코드 수정 없이 분기를 추가한다.
- 100레벨 3차 승급 이후 환생 가능. 현재 직업의 고유 패시브를 영구 계승한다.
- 환생 횟수에 따른 소폭 기본 능력 보너스와 상위 승급 강화가 누적된다.
- 같은 패시브 중복 계승은 최대 5단계. 환생 후 모험가로 시작하며, 20레벨에 다른 직업을 선택할 수 있다.
- 사망만으로는 패시브를 얻지 못한다.

## 최초 제작 범위

일곱 직업의 서로 다른 공격 스타일, 물약, 위험 예고, 수동 방어, 무작위 강화,
승급, 환생 계승, 보스, 승리·사망·재도전, 로컬 저장·복원, 음량·진동 설정.
전투/메타 진행은 표시 코드와 분리해 검증한다.

## 그래픽 교체 기준

가제작 도트는 코드로 직접 그린 원본 임시 자산을 사용한다. 외부 자산 의존 없이 실행한다.
기준 PPU 16, 캐릭터 24×32, 적 24×24~48×48, 타일 16×16, Point 필터·무압축.
최종 캐릭터는 직업별 기본/1차/2차/3차 및 환생 장비를 분리한 레이어가 필요하다.
동작: 대기 4프레임, 공격 6프레임, 피격 2프레임, 사망 6프레임. 방향은 첫 버전 정면.
스킬별 4단계 이펙트 시트(32~128px), 보스 예고 장판, 물약·패시브·강화 아이콘이 필요하다.
최종 아트와 사운드, 실기기 사용성·발열·세이브 호환 검증을 거쳐 출시한다.
